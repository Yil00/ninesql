# CONTEXT.md – NineSQL

Project context for every contributor, human or AI agent. Read it **before** any task.

## In one sentence
NineSQL is an open-source (Apache 2.0) native database client for Debian and Ubuntu, written in Rust with a GPU-rendered GPUI interface, that aims at DBeaver feature parity on the 20 most used open-source engines and imports DBeaver workspaces.

## Where the project stands
- **Current phase**: 3 – SQL editor and results grid, **not started** (see [docs/ROADMAP.md](docs/ROADMAP.md)). Phase 2 (DBeaver import) is **closed** (2026-11-15) after the P2-D review, whose verdict is "phase 2 can close with follow-ups"; its exit criterion is met in tests (snapshots per fixture, DBeaver files byte-identical, 100 connections imported in under 2 s), and the visual pass of the import screens is deferred to P6-F with the rest of the UI. Phase 1 (shell, connections, first drivers) is **closed** (2026-11-15) after the P1-E review, whose verdict is "can close with follow-ups", with an amended exit criterion: the visual pass and the manual run of the exit scenario are deferred to the final tests at the end of the MVP (P6-F), and the Secret Service backend stays off by default, so saved passwords go to the encrypted vault. Phase 0 is done except the items listed below.
- Phase 0 (done): repository and settings (P0-F); GPUI spike with a GO verdict, GPUI from crates.io through `gpui-kit` 0.9.1 under supply-chain controls (P0-A, [docs/spikes/p0-a-gpui.md](docs/spikes/p0-a-gpui.md)); driver API with mock driver, security-reviewed and frozen (P0-B); dev environment with the 20 engines and the "nine" dataset (P0-C, [dev/README.md](dev/README.md)); workspace storage, connection model and secrets skeleton (P0-D); feature parity audit and synthetic DBeaver fixtures from five versions (P0-E).
- Phase 1, wave 1 (landed): the `ninesql` shell – navigator dock, tabs and splits, status bar, multiple windows, 19 actions with a command palette, key-binding overrides and light / dark / system themes from `settings.toml` (P1-A); `ninesql-ssh` with russh tunnels, jump hosts, agent, `known_hosts` and per-hop host-key policies, RSA key files refused (P1-D, ADR-0016); driver API hardening that closes the P0-B review items; the P0-D review follow-ups (workspace lock, rewrite-on-load, scrubbed backups, project UUID scoping keyring items, wider secret detection); and the read-only DBeaver parser with fail-closed mapping (P2-A, [docs/06](docs/06-dbeaver-interop.md)).
- Phase 1, wave 2 (landed): `ninesql-driver-pgwire` for **PostgreSQL only**, with verified TLS, SCRAM-SHA-256, engine-side read-only checked after every statement and integration tests against `dev/` (P1-B, [docs/08](docs/08-engine-capabilities.md#pgwire-postgresql-p1-b)); in `ninesql-core`, the Tokio driver runtime, driver registry, session manager, connect flow, SSH wiring with per-hop host-key policies (`connections.json` schema 2) and confirmation tokens for production statements, init SQL and SSH host keys (P1-D, [docs/02](docs/02-architecture.md)); in `ninesql-secrets`, the encrypted vault, the "ask every time" cache and backend selection keyring → vault → ask, never plaintext (P1-D); settings saved from the UI and the X11 IME crash patched (P1-A follow-ups); the P2-A follow-ups (blank profiles, DBeaver jump-host selection, RSA key file flag, first fuzz runs).
- Phase 1, wave 3a (landed): `ninesql-driver-mysqlwire` for **MySQL and MariaDB** (tested on MySQL 8.4 and MariaDB 11.8), with verified TLS, `KILL QUERY` on a control connection opened during connect (no secret kept after connect), engine-side read-only re-asserted after every statement and integration tests against `dev/` (P1-B, [docs/08](docs/08-engine-capabilities.md#mysqlwire-mysql-and-mariadb-p1-b)); a pgwire fix: a read-only session in manual-commit mode or an explicit transaction could be made writable by the one-shot `SET TRANSACTION ISOLATION LEVEL …, READ WRITE` form, now neutralised by re-asserting `SET TRANSACTION READ ONLY`; in `ninesql-core`, bounded secret resolution (60 s, single-flight reads, at most 8 pending); in `ninesql-secrets`, the vault locked and the "ask every time" cache cleared on sleep and screen lock (`DesktopLockWatcher`, behind the off-by-default `secret-service` feature, not wired into the app yet); in `ninesql-ssh`, `known_hosts` writes serialized across processes. ADR-0018 (patched third-party crates) and ADR-0019 (TLS CA-file semantics) were accepted in this wave.
- Phase 1, wave 3b (landed): `ninesql-driver-sqlite` for **SQLite** on `rusqlite` 0.42 with the bundled SQLite 3.54.1, one dedicated thread per session, engine-side read-only through `OpenMode` (read-only open, `query_only`, an authorizer that allows only reads, no attached databases; verified after every statement), WAL databases opened without creating `-wal` / `-shm` files, and integration tests on temporary files and the "nine" dataset (P1-B, [docs/08](docs/08-engine-capabilities.md#sqlite-sqlite-p1-b)). Two security findings were fixed before merge: Tcl-style bind variables could hide a `WITH … DELETE` from the production confirmation, and a dropped stream or session did not stop its running statement. P1-B is complete for the MVP families.
- Phase 1, driver-API PR (landed 2026-11-15, security-reviewed in three rounds): the classifier refuses `SET [SESSION | LOCAL] TRANSACTION …` with `WRITE` in any comma segment and reads a `WITH` as a read only when its parentheses balance and its main statement lies outside every CTE; `Capabilities::connect` (`ConnectCapabilities`) is checked before any I/O by every driver and at save / import by the core (M2); `ConnectParams::log_statements` follows the connection type's `log_query_text` (L1); the `TlsConfig::ca_file` rustdoc follows ADR-0019 (L3); `HostKeyVerification::AcceptNew` with its own warnings (ADR-0016); `ConnectParams::password_exchange = ScramOnly`, which pgwire enforces (md5, cleartext and trust refused; no channel binding, so it does not stop a relaying man in the middle below `verify-full`) and mysqlwire refuses; `ConnectParams::inside_dbeaver_workspace` (I4), with which sqlite opens a file read-only and immutable; property keys never echoed raw in driver errors ([docs/08](docs/08-engine-capabilities.md)).
- Phase 1, wave 3 (landed 2026-11-15, security-reviewed after fix rounds): the connections UI (P1-C) – a connection dialog whose engines, TLS modes, authentication kinds and properties come from the drivers' declared capabilities, a navigator list with folders, duplicate and delete, production visuals driven by the open session, every `OpenOutcome` handled (vault unlock / create included), a "Lock secrets now" action, the "SCRAM only" toggle, a "Read-only: DBeaver file" badge, password inputs with no reveal and no copy; the pgwire, mysqlwire and sqlite drivers registered in the `ninesql` binary, so they are reachable from a NineSQL window (L5). In `ninesql-core`, `CoreServices` assembles the app at startup (backend keyring → vault → ask, vault always registered and locked, lock watcher, idle lock), `OpenOutcome::NeedsVaultUnlock` and `CoreEvent::SecretsLocked`, `Connection::password_exchange` (`connections.json` schema 3), `inside_dbeaver_workspace` computed for every file endpoint (fail-closed), TLS mode and password exchange checked at save. Sleep / screen-lock locking is in default builds through the new default-on `desktop-lock` feature (zbus only), recorded with its Flatpak permissions in the [ADR-0005 amendment](docs/adr/0005-secrets-storage.md#amendment-p1-d-wiring-2026-11-15). The visual pass is deferred to the final tests at the end of the MVP (P6-F).
- Phase 1 close (2026-11-15): the P1-E review found two deviations from accepted ADRs and several security-relevant decisions with no ADR; they are written up and were accepted by the maintainer the same day: the [ADR-0004 amendment](docs/adr/0004-driver-api-runtime-and-results.md#amendment-sqlite-session-threads-2026-11-15) (one thread per sqlite session), the [ADR-0017 amendment](docs/adr/0017-workspace-lock-rewrite-on-load-and-project-identity.md#amendment-known_hosts-lock-wait-2026-11-15) (bounded `known_hosts` lock wait), [ADR-0020](docs/adr/0020-phase-1-driver-decisions.md) (driver decisions) and [ADR-0021](docs/adr/0021-phase-1-core-secrets-and-storage-decisions.md) (core, secrets and storage decisions). ## Invariants (non-negotiable)
| # | Invariant | Source |
|---|-----------|--------|
| I1 | No secret in clear on disk: passwords, passphrases and tokens live only in the OS keyring (Secret Service) or the encrypted vault; never in config files, logs, history, crash reports or exports | ADR-0005 |
| I2 | No network traffic except to the user's declared connections (and their SSH / proxy hops). No telemetry, no analytics, no phone-home; an update check, if ever added, is opt-in | ADR-0001, 05-security |
| I3 | A read-only connection is enforced at the session level by the driver (engine-side read-only transaction or equivalent), never only by the UI. Destructive statements on a connection typed "production" require explicit confirmation | ADR-0007 |
| I4 | NineSQL never modifies, moves or deletes DBeaver files. Import is read-only; export writes only to a new file the user chooses | ADR-0006 |
| I5 | TLS certificates and SSH host keys are verified by default (rustls, `known_hosts`). Disabling a check is an explicit, per-connection, visibly flagged choice | ADR-0011 |
| I6 | The UI thread never waits on I/O. Every query result is streamed with a memory budget; nothing loads an unbounded result into memory | ADR-0004 |
| I7 | Apache 2.0 only: no GPL / AGPL / SSPL / proprietary code linked into the binary (Zed's GPL crates included), no JVM, no webview | ADR-0001, ADR-0002 |
| I8 | Capabilities are declared honestly per engine: the UI hides or disables what a driver does not support; it never fakes a feature | ADR-0004, docs/08 |

## Glossary
| Term | Definition |
|-------|-----------|
| **Connection** | A saved set of parameters (engine, host, credentials reference, SSH, TLS, type) to reach one database server or file |
| **Connection type** | Dev / Test / Production (DBeaver-compatible), carrying color, auto-commit default, confirmation and read-only rules |
| **Driver** | Engine-specific crate implementing the `ninesql-driver-api` traits (`ninesql-driver-postgres`…) |
| **Family** | Group of engines sharing a wire protocol and therefore one driver (pg-wire, mysql-wire…) |
| **Capability** | A feature a driver declares (metadata kinds, editing, explain, transactions…), read by the UI |
| **Session** | A live connection to a database, owned by the driver runtime, with its transaction state |
| **Result stream** | Batches of rows (Arrow `RecordBatch`) or documents produced by a query, consumed by the grid under a memory budget |
| **Workspace** | NineSQL's own storage: projects, connections, scripts, history (docs/02, ADR-0008) |
| **Vault** | Encrypted local secret store used when no Secret Service is available (ADR-0005) |
| **Import** | One-way conversion of a DBeaver workspace into NineSQL connections (ADR-0006) |
| **Feature id** | `F-<area>-<nn>` identifier of a DBeaver feature in [docs/07-feature-parity.md](docs/07-feature-parity.md) |
