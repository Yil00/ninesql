# ADR-0027: Phase 5 editing, transfer and export decisions

- **Status**: Accepted (maintainer, 2026-11-17; proposed 2026-11-16). It builds on [ADR-0004](0004-driver-api-runtime-and-results.md) (driver API, streamed results under a budget), [ADR-0006](0006-dbeaver-interoperability.md) §7 (export to DBeaver), [ADR-0008](0008-workspace-and-config-storage.md) §1 (a new machine-owned file in the project, §4.1 below, without editing it) and [ADR-0020](0020-phase-1-driver-decisions.md) §2 (MySQL literals: rule unchanged, spelling noted there). The confirmation rules of phase 5 are a separate [ADR-0007 amendment](0007-production-safety-model.md#amendment-phase-5-2026-11-16), also accepted (maintainer, 2026-11-17).
- **Date**: 2026-11-16

## Context
Phase 5 landed on 2026-11-16 on the session branch (commit ccc7215): DML generation in the driver API (P5-B, `crates/ninesql-driver-api/src/dml.rs` and each driver's `dml.rs`), the `ninesql-transfer` crate and the core `TransferService` (P5-C), the export to DBeaver (P5-D, `crates/ninesql-dbeaver/src/export/`, `crates/ninesql-core/src/dbeaver_export.rs`), the core `EditService` (`crates/ninesql-core/src/edit/`) and the UI (P5-A). The task reports, the security reviews of P5-B, P5-C, P5-D and the P5-A core, and the P5 UI review (fixes merged on 2026-11-16, commits 2c613df, df7d51c and 3678abb) listed decisions that are security-relevant, change visible behaviour (update counts on the MySQL family), add a workspace file or set limits. This ADR records them so later work does not undo them by accident. The rustdoc of the modules named in each section is the reference for details; [docs/02](../02-architecture.md#data-transfer-p5-c), [docs/05](../05-security.md#generated-sql-and-row-edits-p5-a-p5-b), [docs/06](../06-dbeaver-interop.md#export-to-dbeaver-p5-d) and [docs/08](../08-engine-capabilities.md#dml-generation-p5-b) describe the behaviour.

## Decision

### 1. DML generation (P5-B)
1. **Two forms per statement.** `dml::generate` returns the statement that is **executed**, with every value a bound parameter, and a separate **preview** with typed literals, used for the DML preview, the copy as SQL `INSERT` and the SQL export. Nothing ever executes the preview form on the user's behalf.
2. **Mode-independent literals.** A preview literal reads back as exactly the value the bound parameter gives in **every** lexical mode of the engine, because a preview or an export may be replayed in another session (P5-B review H1). MySQL family: a string holding a backslash, a NUL, a control or an invisible character is written `CONCAT(_utf8mb4 X'…')`, any other string `'…'` with quotes doubled, so no literal depends on `NO_BACKSLASH_ESCAPES`, `ANSI_QUOTES` or a multi-byte client character set; the `_utf8mb4` introducer makes the string coercible, so the column's collation applies in key comparisons (a `latin1_swedish_ci` or `_as_cs` key), and `CONCAT` makes it a string expression (alone, MySQL stores an introduced hex literal into `JSON` as binary and TiDB reads it as a bit literal for `TIME`). The same form is the driver's inlined parameter (note on [ADR-0020](0020-phase-1-driver-decisions.md) §2). PostgreSQL family: `E'…'` when the text holds `\`, a control or an invisible character; casts to built-in types qualified `pg_catalog.<type>` unless the type is spelled with SQL keywords; `bytea` always `E'\\x…'::pg_catalog.bytea`; a number bare only when its kind matches the column's. `Dialect::dml_literal` carries this contract.
3. **Columns never compared.** A column type without a reliable `=` is never part of a key and is left out of the optimistic-concurrency `WHERE` (reported as unchecked): PostgreSQL `json`, `xml`, the geometric types and their arrays; MySQL family `JSON`, spatial types, `VECTOR`, `BIT` and `FLOAT`. SQLite compares every type.
4. **Update counts are rows matched.** mysqlwire connects with `CLIENT_FOUND_ROWS`, so an `UPDATE` reports the rows it matched (as JDBC drivers do), not the rows whose value changed: an edit that writes an unchanged value still reports one row, and `check_affected` (exactly one row) works. This also changes the count shown for user `UPDATE` statements on MySQL, MariaDB and TiDB. PostgreSQL and SQLite already count matched rows.
5. **Index flags and conservative defaults.** `IndexInfo` gains `valid`, `deferrable`, `nulls_distinct`, `partial` and per-part `expressions` (additive driver-API fields). Their defaults are conservative: not valid, parts unknown. A row key comes only from these flags (`KeyCandidate::from_index`, `choose_row_key`): invalid, not-ready, deferrable, partial and expression indexes never count; the primary key first, then the smallest non-null unique key, then the smallest nullable one.
6. **`TableInfo::transactional`.** `Some(true)` for PostgreSQL and ordinary SQLite tables, read from the storage engine on the MySQL family, `None` when unknown. A table with `Some(false)` (MyISAM, MEMORY, ARCHIVE…) is **never editable**, with no override, since a failed save could not be rolled back; on the MySQL family `None` is refused too.

   > **Note (2026-11-18, P5-E M1).** The rule also applies to the **CSV import**. Before its lease, the import reads the target's `TableInfo::transactional` through the metadata service (`TransferService::import_target`, `ImportTarget`; a table not found counts as unknown). "All or nothing" is refused on `Some(false)`, and on the MySQL family on `None` too (`TransferJobError::NonTransactionalTable`, `TableStorageUnknown`). "Commit every N rows" still runs there, marked non-transactional: the confirmation and the summary say rows cannot be rolled back (`ImportConfirmation::non_transactional`, `ImportSummary::transactional` is `false`), and every row the database accepted is counted as kept. Before this note the import decided from `capabilities.transactions.manual_commit` only, so a failed "All or nothing" import into a MyISAM table reported "nothing was written" while the earlier batches stayed. Tests: `myisam_import_*` in `crates/ninesql-core/tests/transfer_engines.rs` (MySQL, MariaDB).
7. **`NULLS NOT DISTINCT` hook.** `Dialect::supports_unique_nulls_not_distinct()` (PostgreSQL 15 and later, TimescaleDB by its server version) decides whether a unique key whose `NULL`s are not distinct can match a `NULL` key value with `IS NULL`; elsewhere a `NULL` in a nullable unique key refuses the edit.

### 2. Editing (P5-A core)
1. **`QuerySource` provenance.** Only a result produced by the core's own table query can be edited: `table_query`, `build_table_query` and the foreign-key queries return a `BuiltQuery` whose `QuerySource` names the table and the selected columns, and `PendingEdits::new` refuses a result whose columns are not exactly those (name, order, number). A statement the user typed is never editable, so an alias cannot point an edit at other rows. The check is shape-based; a stronger binding needs per-field source columns from the driver API (follow-up).
2. **At most 10 000 changes per save** (`MAX_CHANGES_PER_SAVE`), each a separate bound statement that must change exactly one row; any error, other row count or cancel undoes the whole save. Larger changes are made in several saves or with SQL.
3. **The save leases its session** (§3.3) and refuses a read-only session; transactions and confirmation follow the [ADR-0007 amendment](0007-production-safety-model.md#amendment-phase-5-2026-11-16).

### 3. Transfer (P5-C)
1. **Export file policy.** An export writes only a **new** file the user chose (I4): a temporary file in the target directory created with `O_CREAT | O_EXCL | O_NOFOLLOW | O_CLOEXEC`, mode **`0600`** (exports may hold sensitive data; the final file keeps it), synced, then moved into place with `renameat2(RENAME_NOREPLACE)` (fallbacks: a hard link, then a check and `rename` where neither exists). Replacing an existing file needs an explicit, separate confirmation in the UI; the move then replaces a symbolic link itself, never its target. The target directory is resolved and refused when it is, or lies inside, a DBeaver workspace, NineSQL's configuration, data or state directories, or **`~/.ssh`**, compared by resolved prefix and by `(device, inode)` of the directory and each ancestor at every check. Import files are opened once (`O_NOFOLLOW | O_NONBLOCK`), only if regular, checked with `fstat` and read through that handle.
2. **Formula guard on by default.** CSV and TSV exports and copies prefix with `'` a text cell or header that a spreadsheet would run as a formula (a leading tab or CR, or a first character after Unicode whitespace and format characters among `= + - @ |` and their full-width forms). It can be turned off per export; numbers are never prefixed. The NULL text and the decimal separator are checked against the delimiter, the quote and the guard.
3. **Session leases.** An export, an import and a grid save take their session exclusively (`SessionHandle::lease`), granted only when nothing runs or is queued on it (a paused grid result counts); meanwhile every other statement and transaction command fails with `CoreError::SessionLeased` and metadata loads refuse the session. A lease dropped while its job holds a transaction queues a `ROLLBACK` before it is released. The services wait at most 2 s for a session finishing a statement, then answer "busy".
4. **Limits.** Import `INSERT`s carry at most 1 000 rows, 30 000 parameters and 4 MiB of parameters; CSV files at most 8 GiB, records 1 MiB and 4 096 fields; an import summary keeps the first 100 issues, which never hold a value. Exports have no row or byte limit (rows are written, not kept) and hold at most `(WRITER_QUEUE + 2) × max_batch_bytes` of batches.

### 4. Snippets and filter history
1. **`snippets.json`** (schema 1), one per project, beside `connections.json`: machine-written with ADR-0008's rules (versioned JSON, atomic, `0600`). Names unique without case, at most 128 bytes; bodies at most 64 KiB; at most 1 000 snippets; an optional engine and description. Placeholders `${name}`, `${name:default}`, `${cursor}`, `$$`; values are inserted as typed, and an expansion is editor text the user runs like any other statement, never executed by the snippet code. A body with a URI holding credentials, or a credential word (the history rule) together with a literal typed in the body, is refused; such entries in a hand-edited file are dropped at load and reported. It is not a `connections.json` schema change.
2. **Filter history.** Server-side filters are recorded per connection **in memory only** (at most 50 per connection, 1 024 connections), never on disk, under the history rules of [ADR-0024](0024-phase-3-execution-history-and-preferences-decisions.md) §2: nothing when history is disabled; on production and non-logging types only the shape (columns, comparisons, order), never a value or the raw `WHERE`; elsewhere the whole filter, except a raw text with a credential word or a URI with credentials, and values on a column whose name holds a credential word or longer than 4 KiB. Persisting it needs its own schema decision.

### 5. Export to DBeaver (P5-D)
1. **Mirror input without secrets.** `ExportConnection` and `ExportConnectionType` mirror the core model; the core passes a "saved" flag instead of any secret value or reference. No password, passphrase or token is written, and **no `credentials-config.json`**, not even encrypted: DBeaver asks for passwords.
2. **Skip rather than approximate unsafely.** A connection is skipped, with a report entry, when DBeaver would connect to it differently: a host holding `? & ; # / \ % , [ ]` or whitespace, a database or file path holding `? & ; # %` (pasted unescaped into the JDBC URL, they would override TLS and read-only), an IPv6 address host, a Unix socket, a route NineSQL disabled (`DisabledKind::Route`), an engine without a known DBeaver driver, a connection type the caller did not pass, more than 5 jump hosts, or names and keys that look like secrets. QuestDB is written as PostgreSQL (approximated, reported).
3. **TLS never weaker on the way back.** MySQL-family `verify-full` writes a verifying `mysql_ssl` handler **and** the driver's `sslMode` property (worst case in an old driver: `verify-ca`, never plaintext), with a warning naming the minimum driver; the importer keeps the **stricter** of a TLS handler mode and an `sslMode` property (before P5-D the handler won).
4. **`ninesql-` type ids.** Custom connection types are written as `ninesql-<id>` (at most 64 bytes) with a warning, since DBeaver keeps an existing type of the same id; NineSQL imports them back under the prefixed id.
5. **Read-only and init SQL.** The effective read-only value is written (`read-only: true`, and `readOnlyMode=always` on pgjdbc), with a warning on every read-only connection that DBeaver enforces read-only in its JDBC driver and UI, not engine-side. Init SQL is not written when it mentions a credential word or a URI with credentials, when the connection is read-only and the statement is not a plain read (not classified `Read`, calls a function, holds a TiDB `/*T!` comment, or touches the access mode), or while it is still marked for confirmation after an import.
6. **Files.** A new `data-sources.json` (temporary file, hard link that fails if the name exists, device and inode checked) or a new project folder, never inside a DBeaver location (I4). The directory is checked and then used by path; directory-relative calls are a follow-up (documented residual).

### 6. Grid limits (P5 UI review)
1. **No GIF or animated PNG preview.** The value panel previews only single-frame PNG and JPEG images (`sniff_image`, `crates/ninesql-grid/src/viewer.rs`), within the existing limits (16 MiB, 8 192 pixels a side, 4 096 × 4 096 pixels). GIF is refused (`ImageRefusal::GifNotSupported`): GPUI decodes every frame of a GIF with no limit, so a small file with thousands of frames, or a frame rectangle larger than its logical screen, would expand without bound (I6). A PNG with an `acTL`, `fcTL` or `fdAT` chunk (APNG) is refused for the same reason (`AnimatedNotSupported`), and so is a PNG whose chunks do not walk cleanly from `IHDR` to `IEND`. A JPEG is previewed only when exactly one start-of-frame lies before its first start-of-scan (none is refused), so the size checked is the size the decoder allocates. A refused value is shown in the hex viewer with a note ("GIF preview not supported; showing hex."). Nothing is decoded before these checks.
2. **Decoded images are evicted.** A preview image that is replaced or no longer shown (another cell, viewer or result, the panel closed) is removed from GPUI's asset cache and from the sprite atlas of every window at the end of the frame, and every cached image when the results view is released, so decoded bitmaps do not accumulate outside the result's memory budget (I6). *Note (2026-11-17, second security re-review M-B, L-B):* when the results view is released there is no window at hand, so the decoded image is kept from the frame that showed it and removed from every window's sprite atlas through `App::drop_image`, not only from the asset cache; an image no frame laid out is evicted without being looked up, so no decode is started only to be thrown away.
3. **Client-side sort bounded at 200 000 rows.** The client-side sort runs on the UI thread over the loaded rows (`MAX_CLIENT_SORT_ROWS`, `crates/ninesql-grid/src/rows.rs`). Above 200 000 loaded rows it is refused, or dropped when more rows arrive while it applies, and the grid says to sort on the server instead; each row's sort key is read once (numbers parsed once, text forms built only for a column that mixes types), never in the comparison. Client-side filters are not bounded by this limit. The limit is a fixed constant, not a preference.

## Consequences
- Previews, copies and SQL exports can be replayed in any session mode of the engine; engine tests run both forms and compare rows, and replay MySQL-family previews across `sql_mode`s.
- MySQL, MariaDB and TiDB users see matched-row counts for their own `UPDATE` statements (documented in [docs/08](../08-engine-capabilities.md#dml-generation-p5-b)).
- Some tables cannot be edited in NineSQL (no key, non-transactional or unknown storage engine, no savepoints in manual-commit mode); the UI says why (I8).
- A new driver must fill the `IndexInfo` flags and `TableInfo::transactional` honestly, or its tables are not editable: the defaults refuse.
- `snippets.json` is a new workspace file to migrate when its schema changes; the filter history is lost on restart.
- The DBeaver export depends on DBeaver behaviour not checked automatically (TLS handler and property merge, host-key checking, jump hosts before 24.3, folder and user keys on 22.x to 25.x): the [manual protocol](../06-dbeaver-interop.md#manual-check-in-dbeaver-maintainer) must run before a release claims it.
- GIF and animated PNG values cannot be previewed until NineSQL has a decoder that bounds frames itself; they stay readable in hex. Some valid JPEGs (several frames, or a header the walk does not accept) are not previewed either.
- A user with more than 200 000 rows loaded must sort on the server ("Sort table by column…" on a table tab, or `ORDER BY` in the query); raising the limit needs a sort off the UI thread first.
- Changing any rule above (a weaker file policy, the guard off by default, persisting filter values, exporting a credentials file) needs a new ADR and a security review.

## Rejected alternatives
- **Show the bound form with `?` placeholders as the preview**: the user could not read what will change; a preview with literals of the current session mode only would change meaning when replayed elsewhere (H1).
- **MySQL `CONVERT(X'…' USING utf8mb4)`** (the P5-B first form): not coercible, so a `latin1_swedish_ci` unique key matched two rows and an `_as_cs` key failed with error 1267.
- **Keep the affected-rows count on the MySQL family**: an edit writing an unchanged value would report zero rows and fail the exactly-one-row check.
- **Pick the key from the result's column names or from any unique index**: an alias or a partial, deferrable or invalid index could identify more than one row.
- **Edit non-transactional tables with a warning**: a failed save would leave part of it written with no way back.
- **Let any result be edited when its columns look like a table's**: an aliased column in a typed statement could point the edit at other rows.
- **Write exports with the user's umask, or in place**: other local users could read the data, and a cancelled export would leave a partial file under the chosen name.
- **Formula guard off by default**: exported data from a database is untrusted input for a spreadsheet.
- **Persist the filter history in `history.sqlite` now**: filter values may be sensitive and their retention rules are not decided.
- **Preview GIF and APNG through GPUI's decoder with a file-size cap only**: the byte size says nothing about the frame count or the decoded size, so a small file could still exhaust memory.
- **Preview only the first frame of a GIF**: GPUI's image loader decodes every frame it is given, so this needs a bounded decoder of NineSQL's own (a follow-up), not a setting.
- **Sort any number of loaded rows on the client**: a sort of millions of rows on the UI thread would freeze the window (I6); the server sorts every row anyway, not only the loaded ones.
- **Export saved passwords encrypted in `credentials-config.json`**: DBeaver's file encryption uses a fixed key, so it would be a plaintext secret on disk (I1).
