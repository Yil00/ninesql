The test itself only asserts under 3 s. Not measured: the time to the first frame showing rows, a release build, the `big_events` table of the "nine" dataset.
- **Scrolls without dropped frames on the reference machine**: **not measured**. It needs a display and a real GPU: deferred to the local protocol of P3-E (maintainer) and the MVP-end tests ([P6-F](#phase-6--hardening-and-v010-release)). The headless checks (one million rows, visible window lookup, copy) run on the CPU only and say nothing about frame times.
- **Stays under the memory budget**: tested headless. The grid's per-execution account stops at the budget and releases the stream (`the_budget_stops_ingestion_and_releases_the_stream`, `crates/ninesql-grid/tests/headless_perf.rs`); every driver's batches stay within the fetch budget (`conformance::assert_batches_within_budget`). The process RSS at the budget is not measured (local protocol, step 5).
- **Can be cancelled**: tested against the dev PostgreSQL (cancel while the 1 M-row result streams, same test) and in the UI (`cancel_stops_the_running_statement`, `TestAppContext` with the mock driver).
- **`DELETE` without `WHERE` on production asks for confirmation**: tested against the dev PostgreSQL (same test) and in the UI (`a_production_delete_without_where_is_confirmed_then_resumed`).

Next: the phase 3 review and the maintainer's decision to close the phase; the real-GPU run of the P3-E protocol; phase 4 (navigator and metadata), which also fills the editor's object completion.
