# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/). Released sections are generated at release time from Conventional Commits ([RELEASE.md](RELEASE.md)).

## [Unreleased]
No version has been released yet. This section summarizes, for users, everything since the start of the project: phases 0 to 5, the follow-ups done before phase 6 and the phase 6 packaging and documentation. "Changed", "Fixed" and "Security" describe changes to the behaviour of earlier development builds. What does not work yet is listed in the [known limitations](docs/user-guide/known-limitations.md); measurements of start time, memory and scrolling on real hardware are not available yet.

### Added
- **Application window** (GPUI, rendered on the GPU): database navigator, editor tabs and splits, several windows, status bar, a command palette listing every action, default key bindings for every action and overrides in `settings.toml`, light / dark / system themes, font sizes and zoom saved back to `settings.toml` (comments kept), "Show settings problems".
- **Eight engines**: PostgreSQL, MySQL, MariaDB and SQLite, plus TimescaleDB, YugabyteDB (YSQL) and QuestDB through the PostgreSQL-protocol driver and TiDB through the MySQL-protocol driver, each with its declared capabilities. The server must be the engine chosen (checked at connect). QuestDB: no TLS, password only through a strict SSH tunnel, no transactions, no row editing. TiDB: no TLS yet.
- **Connections**: a connection dialog whose engines, TLS modes, authentication kinds and driver properties come from the drivers; "Test connection"; folders, duplicate, delete; a URL pasted to fill the fields (refused when it carries a password); "Show connection problems"; a "Security warnings" notification for weakened sessions.
- **TLS** verified by default ("Verify CA and host name"), with "Verify CA", "Encrypt only" and "Disabled" as flagged choices; a per-connection CA file that replaces the system trust store (required by "Verify CA"); client certificates; never a fallback to plain text. "SCRAM only" on PostgreSQL-protocol engines.
- **SSH tunnels** with jump hosts, SSH agent, passwords and Ed25519 / ECDSA key files, a per-hop host-key policy ("Strict (confirm unknown keys)" by default, "Accept new keys", "Do not verify"), fingerprint confirmation of unknown keys, changed keys refused, NineSQL's own `known_hosts` (`~/.ssh/known_hosts` read, never written).
- **Connection types** Development, Test and Production (and custom or imported types) with colors, a production frame around the editor area, type and read-only badges, confirmations, manual commit by default on production, and statement text kept out of logs and history.
- **Read-only connections enforced by the database engine**, checked after every statement, the session closed if read-only is lifted; on QuestDB and TiDB accepted only when the server itself refuses writes for the account, otherwise refused.
- **Secrets**: an encrypted vault (`vault.bin`, Argon2id and XChaCha20-Poly1305) with a master password of at least 12 characters, locked at every start; "Ask every time" passwords, asked at each connect and never kept; a desktop keyring backend (Secret Service), off in default builds; locking on "Lock secrets now" (`Ctrl+Alt+L`), after 15 minutes without use, on sleep and on screen lock (systemd-logind), with a "Secrets locked" notice.
- **DBeaver import** ("Import from DBeaver", "Import from DBeaver: choose folder", a first-run offer): detection of native, Flatpak and Snap workspaces; a preview of every connection created, updated, imported disabled or not imported, with per-connection "Test"; saved passwords moved to the vault or keyring; connection types created or made stricter, never weaker; JDBC driver properties converted or dropped with a report entry; idempotent re-import that keeps your own changes; "Enable connection" for connections imported disabled; an import report in the project; limits and "Cancel" for large or slow sources.
- **SQL editor**: syntax highlighting; "Execute statement", "Execute selection", "Execute script" with each engine's own splitting rules (psql, the mysql client's `DELIMITER`, SQLite triggers); bound parameters (`:name`, `?`, `$1`… per engine) with a panel that never saves values; completion of keywords, aliases, CTE names and loaded schemas, tables, views, routines and columns; find and replace, multi-cursor, line comments, mouse folding; error positions with "Go to error" (`F8`); bidirectional control characters flagged; cancel, statement timeouts, commit and roll back; "Format SQL"; snippets from the project's `snippets.json`.
- **Script files and session restore**: "New script", "Open script…", "Save script", "Save script as…", "Connect script connection"; scripts in the project's `scripts/` linked to their connection; at the next start the saved scripts of each window reopen with their connection, cursor and layout, never unsaved text and never connecting by themselves.
- **Query history** in `history.sqlite` (readable by you only), without parameter values, without production statements and without statements holding credentials; preferences under `[execution]`, `[history]` and `[confirmations]` in `settings.toml`.
- **Results grid**: virtualized grid with paging, a memory budget per run (256 MiB by default), result tabs, update counts and notices; a result left waiting is closed after an idle time (240 s by default), keeping the loaded rows; copy as tab-separated text, CSV, Markdown, JSON or SQL `INSERT`; grid, record and text views; value viewers (text, JSON, XML, hex, PNG and JPEG images); aggregate and metadata panels; client-side sort and filter of the loaded rows.
- **Navigator**: a lazy object tree per engine (schemas, tables, views, materialized views, columns, constraints, foreign keys, indexes, triggers, partitions, sequences, types, routines, events, as each engine has them), "Load more", refresh, include / exclude filters saved per project, "Find object" over the loaded metadata, an object editor ("Properties", "Columns", "Keys / Constraints", "Indexes", "DDL"), "Generate SQL" templates that never run, "Show DDL" and "Copy DDL", visible markers for unusual characters in names.
- **Data editing**: "Open table data", then edit cells (in a dialog), insert, duplicate and delete rows as pending changes; "Preview changes…" with the exact statements; "Save changes", each statement required to change exactly one row and the whole save undone otherwise; one confirmation for a save on production; saves under a savepoint in manual-commit mode; server-side filter and sort with bound values; "Open referenced rows" and "Open referencing rows".
- **Export and import**: export of results and tables to CSV, TSV, JSON, JSON Lines, SQL `INSERT`, Markdown and HTML, streamed in bounded memory, reads only, in an engine-side read-only transaction where the engine has one, to a new private file, with a spreadsheet formula guard on by default; CSV import with a preview, a column mapping, "All or nothing" or "Commit every 1000 rows", and one confirmation on production.
- **Export connections to DBeaver**: chosen connections written to a new DBeaver `data-sources.json` or project folder, without any password; connections DBeaver could not reproduce safely skipped with a reason; read-only connections warned that DBeaver enforces read-only more weakly.
- **Packaging** (no package published yet): a `.deb` for Debian 12 / 13 and Ubuntu 22.04 / 24.04 (amd64), built with `make deb`, with a desktop entry, icons, AppStream metadata, a man page (`man ninesql`) and the licenses of the bundled crates, no install or removal script; a Flatpak manifest with minimal permissions (not built yet); a release workflow that builds the `.deb` twice and compares it, writes an SBOM and signs the files with cosign ([packaging/README.md](packaging/README.md)).
- **`ninesql --version` and `ninesql --help`** (also `-V` / `-h`), answered without opening a window; any other argument exits with status 2.
- **Application id `io.github.yil00.NineSQL`** for the window (Wayland app id, X11 `WM_CLASS`), the desktop entry, the icons, AppStream and the Flatpak, so the desktop shows NineSQL's name and icon.
- **Documentation**: a [user guide](docs/user-guide/README.md) and step-by-step [tutorials](docs/tutorials/README.md).
- **For contributors**: a dev environment with the 20 planned engines in containers and a sample dataset ("nine"), a root `Makefile`, CI with driver integration tests against eight engines and a macOS build job.

### Changed
- `connections.json` moved from schema 1 to schema 5 during development (SSH host-key policies, the password exchange, the imported init SQL marker, default schema and catalog, auto-commit override, disabled reason, DBeaver source workspace). Each migration keeps the previous file as `connections.json.bak`; an older NineSQL refuses a newer file.
- Update counts of `UPDATE` statements on MySQL, MariaDB and TiDB are now the number of rows matched (as JDBC drivers report them), not the number whose value changed.
- Locking on sleep and screen lock is on in default builds, and the lock watcher reconnects after a lost system bus instead of stopping.
- "Ask every time" passwords are asked at every connect and never cached in memory (final decision).
- The DBeaver import keeps the stricter TLS mode when a DBeaver connection sets it both in its SSL settings and in a driver property.
- The key bindings of the data editing, export, import, "Format SQL", snippet and DBeaver export actions work from the SQL editor (they were reachable from the command palette only).
- A symbolically linked `settings.toml` is followed when it resolves to a regular file you own.
- Building from source needs Rust 1.89 or newer.

### Fixed
- X11: a crash on the first input-method preedit with a non-ASCII character.
- A paused result lost its whole session after 300 s on PostgreSQL and MySQL; it is now closed by NineSQL before that, keeping the session and the loaded rows.
- Results of a script with many result sets were not bounded; each result set now counts against the memory budget, and one run keeps at most 1 000 result tabs.
- A CSV import into a table that cannot roll back (MyISAM and the like) claimed that nothing was written; "All or nothing" is no longer offered there, and the import summary no longer contradicts itself in "Commit every N rows" mode.
- An "All or nothing" import into a table created after its schema was loaded was refused on the MySQL family.
- The confirmation script view could clip the end of a long line; it now wraps to the width of its box.
- After a failed undo of a save, the session is closed so the server rolls back.
- A dropped result or session did not stop its running SQLite statement.
- Several NineSQL processes or threads could write `known_hosts` at the same time; a slow keyring could block a connect without limit.
- A history retention change could leave one entry over the new limit.

### Security
- The statement classifier, which drives production confirmations and client-side read-only refusals, now catches: `EXPLAIN` / `DESCRIBE` forms that run their statement (options in parentheses, `ANALYZE` in any spelling), statements starting with `ANALYZE`, `CREATE OR REPLACE` (destructive), `SET TRANSACTION …, READ WRITE`, `WITH` statements whose main statement is not found, MySQL conditional executable comments, user variables and `$` in names used to hide a `WHERE`, PostgreSQL comments ended by a carriage return, keywords used as names, trigger bodies, and functions with side effects (sequences, locks, `pg_sleep`, server file access, replication and maintenance functions, TimescaleDB data functions, QuestDB and TiDB specific statements, MySQL `SLEEP`, `BENCHMARK`, `LOAD_FILE`…), which are now confirmed on production and refused in read-only sessions.
- PostgreSQL: a read-only session in manual-commit mode or in an explicit transaction could be made writable by `SET TRANSACTION … READ WRITE`; the driver now re-asserts read-only inside every transaction block.
- SQLite: Tcl-style bind variables could hide a `DELETE` from the production confirmation.
- TiDB: a read-only session now also requires an account the instance's read-only mode covers (no `RESTRICTED_REPLICA_WRITER_ADMIN`, `SUPER` or `ALL PRIVILEGES ON *.*`), a refused write probe, and closes the session when the account's active roles change.
- TiDB exports no longer claim an engine-side read-only transaction (TiDB has none): they are refused on production unless the connection is read-only, and warned otherwise.
- DBeaver import: a re-import cannot redirect a saved password to another server (secrets are kept only while engine, host, port, user, TLS, SSH route and key file are unchanged); a weaker or different TLS setting is applied only when accepted per connection; imported init SQL is always confirmed once, whatever the connection type; DBeaver files are left byte-identical.
- A file inside a DBeaver workspace is opened read-only by NineSQL as well as by the driver.
- A file chosen through the Flatpak document portal is checked at its host path for a DBeaver workspace; when the portal cannot say, a SQLite file there opens read-only.
- A new vault master password must be at least 12 characters long.
- Driver error messages no longer repeat a driver property key raw.
- The plain `Ctrl+C` copy now has the spreadsheet formula guard, as the CSV copy and export do.
- GIF and animated PNG values are no longer decoded for preview (an unbounded decode); PNG and JPEG previews are limited in size and pixels, and images no longer shown are released from memory.
- The CSV import confirmation is bound to the file, the target table and the CSV options as shown.
