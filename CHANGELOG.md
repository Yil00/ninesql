# Changelog

All notable changes to this project are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses [Semantic Versioning](https://semver.org/). Released sections are generated at release time from Conventional Commits ([RELEASE.md](RELEASE.md)).

## [Unreleased]
### Added
- Repository bootstrap: documentation, ADR-0001 to ADR-0011, ROADMAP, agent definitions, CI, Rust workspace skeleton.
- GPUI spike (`crates/ninesql-ui/examples/spike.rs`): dock, tabbed SQL editors with tree-sitter highlighting, virtual table of 1 000 000 rows; go / no-go note in `docs/spikes/p0-a-gpui.md`. GPUI and `gpui-component` come from crates.io through an exact pin of `gpui-kit` 0.9.1, with a snapshot verification script (`scripts/verify-gpui-snapshot.sh`) and `cargo deny` bans (ADR-0013).
- Driver API (`ninesql-driver-api`): driver, session, metadata, dialect and capability traits, connection parameters with secret handles, Arrow result streams under a fetch budget, engine-side read-only rules, a mock driver and conformance helpers. Reviewed and frozen.
- Dev environment (`dev/`): the 20 engines in containers pinned by digest, bound to `127.0.0.1`, in `core` / `sql` / `nosql` / `heavy` / `all` profiles, with the fake "nine" dataset, `engines.json`, `ready.py` and a CI workflow.
- Workspace storage (`ninesql-storage`), connection model and workspace service (`ninesql-core`), secret store trait with an in-memory store and a Secret Service backend on `secret-service` 6 (`ninesql-secrets`, ADR-0012).
- Synthetic DBeaver workspace fixtures written by five DBeaver CE versions (22.3.5 to 26.2.4), with tests that decrypt and audit their fake credentials.
- ADR-0012 (Secret Service client and Rust 1.89 floor), ADR-0013 (GPUI source and supply-chain controls), ADR-0014 (dev profiles).
- Dependabot updates for the dev container images.
- `ninesql` application shell (P1-A): navigator dock, editor tabs and splits, status bar, multiple windows; 19 actions with default key bindings and a command palette; key-binding overrides, light / dark / system themes, fonts and zoom read from `settings.toml` at startup. Settings are not saved from the UI yet.
- SSH tunnels (`ninesql-ssh`, P1-D): russh with `ring`, jump hosts, `ssh-agent`, Ed25519 / ECDSA key files, `known_hosts` checks and per-hop host-key policies (ADR-0016). RSA key files are refused until RSA support is enabled. Not wired into the core yet.
- DBeaver workspace parser (`ninesql-dbeaver`, P2-A): read-only detection of native, Flatpak, Snap and custom workspaces; `data-sources*.json` model; `credentials-config.json` decryption into zeroized buffers; mapping to a mirror of the core connection model with fail-closed rules (network profiles, unknown or unreadable handlers, SSH forwarding target mismatch), per-project limits and a `verify-full` TLS default; cargo-fuzz targets for both decoders (not run yet). Import flow and persistence are not done.
- Driver API: execution-scoped cancel with a busy-until-confirmed rule, timeout watchdog, per-row and header budget accounting, document truncation and depth limit, `extra_reserved_properties`, `retains_secret_after_connect`, wider side-effect classification and SQL-form secret redaction, new conformance helpers.
- Workspace storage: single-writer lock `$XDG_DATA_HOME/ninesql/ninesql.lock`, immediate rewrite of files holding a plaintext secret, scrubbed migration backups, directory ownership and symlink checks; `project.json` v2 with a stable project UUID that scopes Secret Service items, with duplicate resolution (ADR-0017).
- GPUI snapshot audit log (`docs/audits/gpui-snapshot.md`).
- ADR-0015 (0BSD license allowed), ADR-0016 (SSH RSA keys and host-key policies); ADR-0017 (workspace lock, rewrite-on-load and project identity) accepted.
- PostgreSQL driver (`ninesql-driver-pgwire`, P1-B), PostgreSQL only: built on the `postgres-protocol` codec with tokio and rustls (`ring`); TLS `disable` / `require` / `verify-ca` / `verify-full` (a CA file is trusted alone; `verify-ca` requires one), SCRAM-SHA-256 with the server signature verified, md5 allowed with a warning, cleartext only over verified TLS or a verified loopback SSH tunnel; property allowlist and extra reserved keys; engine-side read-only verified after every statement; streamed portals in an implicit read transaction committed only on completion; idle cursors closed on cancel or drop; cancel requests over the session's TLS settings; schema-qualified internal queries; integration tests against `dev/` (PostgreSQL 18). The dev PostgreSQL service also accepts TLS with a throwaway CA generated at first start.
- Driver runtime and session manager (`ninesql-core`, P1-D): Tokio runtime, driver registry with reserved-property validation, session manager with bounded channels and a reserved terminal event, cancel that waits for the previous statement (`WaitingForPreviousCancel`, `StillCancelling`), connect flow with secrets resolved on the blocking pool, "ask every time" prompts, read-only from the connection type (a session that is not read-only is closed), TLS `server_name` behind SSH tunnels, SSH wiring with per-hop host-key policies, single-use confirmation tokens for production statements, init SQL and SSH host keys, and session events where `SessionClosed` is never dropped.
- Encrypted vault (`ninesql-secrets`, P1-D): `vault.bin` format v1, Argon2id (m = 64 MiB, t = 3, p = 1 by default) and XChaCha20-Poly1305 with a key-check tag, padding and size limits, idle lock on `CLOCK_BOOTTIME`, back-off on failed unlocks, master password change; an in-memory "ask every time" cache; backend selection keyring → vault → ask, never plaintext; Secret Service probe (5 s) and method (25 s) timeouts. The Secret Service backend stays off by default.
- Settings saved from the UI (P1-A): theme, fonts, zoom (`[appearance] zoom`) and key bindings are written back to `settings.toml` with `toml_edit` (comments and unknown keys kept), debounced on a background task, atomically with mode `0600`; never over a newer, invalid or unreadable file.
- DBeaver import report: SSH key files named as RSA (or of unknown type) are flagged (ADR-0016); first cargo-fuzz runs of both decoders recorded (300 s each, no crash).
- MySQL and MariaDB driver (`ninesql-driver-mysqlwire`, P1-B), tested on MySQL 8.4 and MariaDB 11.8: client/server protocol written on tokio and rustls (`ring`), no new dependency; same TLS modes and trust rules as pgwire, never a fallback to plain text; `caching_sha2_password` and `mysql_native_password`, the password itself sent only over a protected transport (full `caching_sha2_password` authentication and `mysql_clear_password` refused otherwise, the server's RSA key never requested); a server of the other engine refused; property allowlist applied as inert literals; parameters inlined as hexadecimal literals; rows read as the consumer asks; `KILL QUERY` on a control connection opened during connect, so no secret is kept after connect; engine-side read-only read back and re-asserted after every statement; integration tests against `dev/`. TiDB is not declared. The dev MySQL and MariaDB services accept TLS with a throwaway CA and seed the dataset in `utf8mb4`.
- Sleep and screen lock (`ninesql-secrets`): `LockHooks` and `DesktopLockWatcher` lock the vault and clear the "ask every time" cache on logind `PrepareForSleep(true)` (under a sleep delay inhibitor), the session `Lock` signal and `LockedHint`; logind signals are checked for sender and destination; the watcher locks once and stops if the bus is lost. Behind the `secret-service` feature (off by default) and not wired into the application yet.
- ADR-0018 (patched third-party crates) and ADR-0019 (TLS CA-file semantics: a CA file is the only trust anchor, `verify-ca` requires one) accepted.

### Changed
- Minimum Rust version raised to 1.89 (ADR-0012).
- Feature parity inventory audited against DBeaver 26.2.4: 22 rows corrected, 14 added, 2 unverified.
- `connections.json` moves to schema version 2 (optional per-hop `host_key_policy`, strict when absent; a version 1 file is migrated on load and the original kept as `connections.json.bak`). An older NineSQL refuses connections.json schema 2: to downgrade, restore connections.json.bak (connections created or edited since are lost).
- A symbolically linked `settings.toml` is now followed when it resolves to a regular file owned by the user (it was refused).
- DBeaver import: jump servers are selected as DBeaver does (`jumpServer.count`, default and maximum 5; user name in `.name`; canonical indices; strict `enabled`; hops DBeaver does not use are reported with their secrets and configured hosts); a blank network-profile value counts as a profile reference in every scope.

### Fixed
- Secret resolution in the core is bounded: one deadline per connect (`ManagerConfig::secret_timeout`, default 60 s), single-flight reads with at most 8 store calls pending, a timeout or a panicking store task reported as `SecretError::Unavailable`, and a connect abandoned when its caller goes away.
- SSH `known_hosts` writes are serialized across threads and NineSQL processes (process-wide mutex, then the workspace lock, waited for at most 2 s); the user `known_hosts` is re-read under the lock, so a key revoked since the load is refused.
- X11: crash on the first IME preedit with a non-ASCII character, fixed by patched copies of `xim-ctext` 0.3.0 and `zed-xim` 0.4.0-zed under `crates/patches/` (`[patch.crates-io]`, exact pins, checked in CI by `scripts/verify-patches.sh`).

### Security
- pgwire: a read-only PostgreSQL session in manual-commit mode or in an explicit transaction could be made writable by the one-shot `SET TRANSACTION ISOLATION LEVEL …, READ WRITE` form (the affected code was never released). The driver now runs `SET TRANSACTION READ ONLY` after every statement inside a transaction block and closes the session if it fails; regression tests cover savepoints and aborted transactions.
